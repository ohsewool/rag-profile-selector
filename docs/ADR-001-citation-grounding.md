# ADR-001: 인용 grounding 계층 — RAG와 문서 증거 모델의 결합

- 상태: 승인 (2026-08-19)
- 배경: `document-intelligence`를 독립 프로젝트로 유지하는 대신 이 저장소의 검색 평가와 결합하기로 한 포트폴리오 결정

## 결정

검색 식별자와 문서상 위치를 잇는 **grounding 계층**(`src/rag_profile_selector/grounding.py`)을 이 저장소에 둔다. `document_intelligence`는 당분간 형제 저장소로 두고 import 경계로만 의존한다.

물리적 병합(코드를 이 저장소로 옮기기)은 하지 않는다. 두 저장소의 커밋 이력이 각각 독립된 작업 증거이고, import 경계만으로도 결합의 실효성은 이미 테스트로 증명되기 때문이다. 병합 여부는 공개 시점에 다시 판단한다.

## 왜 이 계층인가

기존 검색 평가는 "맞는 청크를 가져왔는가"에서 멈춘다. 독자가 실제로 묻는 것은 **"이 인용이 문서의 어디를 가리키며, 그 위치가 맞는가"**인데, 식별자 단위 precision/recall은 이 질문에 답할 수 없다.

grounding 계층이 드러내는 것은 기존 지표가 못 보는 세 가지 실패다:

| 실패 | 식별자 지표에서 보이는 모습 | 실제 결과 |
|---|---|---|
| **ungrounded** | 평범한 오답 하나 | 독자에게는 아무 데도 닿지 않는 인용 |
| **misplaced** | 정답 (precision 1.0) | 답은 맞고 포인터가 틀림 |
| **coarse** | 정답 | 구역이 있는데 페이지 단위로만 인용 |

`tests/test_grounding.py::TestComplementarityWithRetrievalMetrics`가 이 논지를 직접 보인다 — 검색 지표가 완전히 동일한 두 실행이 인용 정확도에서는 1.0과 0.0으로 갈린다.

## 설계 선택

1. **인덱스는 문서에서 만든다.** 식별자→위치 매핑을 따로 선언받지 않고 `Document`를 순회해 구성한다. 실재하지 않는 구역으로 grounding되는 상황 자체가 불가능해진다.
2. **확인 불가한 인용은 정답이 아니다.** gold에 없는 식별자는 무시하지 않고 misplaced로 센다. 아무도 확인해줄 수 없는 인용을 정확하다고 부를 근거가 없다.
3. **grounding rate와 정확도를 분리한다.** grounding에 실패한 항목은 grounding rate만 낮추고, 페이지·구역 정확도는 grounding된 것에 한해 계산한다. 두 종류의 실패를 한 숫자에 섞지 않는다.
4. **좌표는 옮기지 않고 참조한다.** `to_evidence_citation()`이 문서 모델의 `EvidenceCitation`/`RegionReference`로 되돌려주므로, 좌표 검증 로직은 여전히 `document-intelligence`의 것이다.

## 남은 작업

- 한국어 공문서로 평가 코퍼스 구성 (실 데이터 확보 방식 결정 필요)
- 프로파일별 인용 정확도 비교 실험 — 적응형 검색이 인용 품질에도 영향을 주는가
- 부산물로서의 벤치마크 공개 여부 판단
